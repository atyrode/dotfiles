# sops

Who may read the fleet's secrets, in the layout the `clan` CLI keeps
([docs/secrets.md](../docs/secrets.md) has the model and what a leak costs).
Only public halves live here: `users/<name>/key.json` and
`machines/<name>/key.json` each hold an age recipient and its type, nothing
else, and the `secret-shapes` check refuses anything more. The values
themselves are generated by clan vars into [`vars/`](../vars/README.md),
encrypted to the machines that may read them and to every user here.

## Two identities

- `users/alex` is the operator's daily identity, minted inside the Secure
  Enclave of the registered Mac by `atyrode operator init` and unlocked by
  Touch ID on every decryption. Its private half has no exportable form.
- `users/alex-recovery` is the software key whose only copy is the break-glass
  note in Bitwarden. It is registered from day one so that a lost Mac costs a
  re-encryption and nothing more; nothing in this repository reads it.

Every machine has one identity of its own under `machines/<host>`, generated
on that machine and never copied anywhere.

## The key on a machine

Both machine classes hold their private key at `/var/lib/sops-nix/key.txt`,
root-owned, mode 0600 under a mode-0700 directory; sops-nix is pointed at it
by [`modules/shared/clan-machine.nix`](../modules/shared/clan-machine.nix) and
`atyrode identity init` writes the same path. Clan's own machine-key flow
would mint the key on the operator's machine and copy it over SSH; this fleet
takes the path clan tolerates instead, so no private key ever travels.

## Ceremonies

Registration is always run in a checkout of this repository on the Mac; the
recipient (`age1...`) is public and is what the on-machine ceremony prints.

Enrol a machine:

```sh
atyrode identity init                          # on the machine, once; prints the next line
clan secrets machines add <host> age1...       # on the Mac, in a checkout; writes machines/<host>/key.json
clan vars generate <host>                      # once a generator exists; encrypts its values to the machine
```

Enrol the operator (the Mac, once):

```sh
atyrode operator init                          # mints the enclave key; prints the next line
clan secrets users add alex age1se1...         # writes users/alex/key.json
```

Retire a machine or a leaked key:

```sh
clan secrets machines remove <host>
clan vars fix <host>                           # re-encrypts what it could still read; rotate the values a leaked key had
```

`age-plugin-se` is on the Mac's `PATH` through the `security` capability,
which is all `sops` needs to use the enclave identity; no `age.plugins`
entry is declared, because it would make the Linux machines build the plugin
they cannot use.
